# ود حنين — حزمة النشر الإنتاجي

هذه الحزمة تحتوي على واجهة عربية متجاوبة للجوال والكمبيوتر، وخادم Node.js/Express، وإعداد PostgreSQL، وملف نشر Render.

## مهم قبل الاستخدام الفعلي
- لا يمكن ضمان أن أي خادم لن يتعرض لأي خطأ مطلقًا. تم تضمين فحص صحة `/health`، وفشل بدء التشغيل عند عدم توفر قاعدة البيانات، لكن يلزم اختبار تشغيلي ومراقبة ونسخ احتياطية بعد النشر.
- هذه الحزمة ليست منشورة على الإنترنت بمجرد تنزيلها. يلزم حساب استضافة، وقاعدة بيانات مدارة، وإكمال خطوات النشر والموافقة على أي رسوم. ملف `render.yaml` يطلب خدمة ويب مدفوعة وقاعدة بيانات مدارة؛ تحقق من الأسعار الحالية قبل الموافقة.
- لا توجد هنا بيانات اعتماد نينجا أو واجهة API رسمية من نينجا؛ لذلك النظام لا يسحب بيانات نينجا تلقائيًا. الربط الحقيقي يتطلب API رسمية ومفاتيح مصرحًا بها.
- قبل إضافة بيانات مندوبين حقيقية، اختبر نسخة منفصلة، واضبط النسخ الاحتياطي، وراجع الصلاحيات والاحتفاظ بالموقع الجغرافي. لا تتبع مواقع المندوبين إلا بموافقتهم وإشعارهم.

## النشر على Render
1. أنشئ مستودعًا خاصًا في GitHub وارفع جميع ملفات هذه المجلدات إليه.
2. افتح لوحة Render وأنشئ Blueprint جديدًا من المستودع الذي رفعته.
3. راجع الخطة والتكلفة، ثم وافق على إنشاء خدمة الويب وقاعدة PostgreSQL.
4. عيّن `ADMIN_EMAIL` و`ADMIN_PASSWORD` في إعدادات الخدمة إلى بريدك وكلمة مرور فريدة قوية. لا ترسل كلمة المرور في محادثة عامة.
5. انتظر نجاح Build وDeploy، ثم افتح رابط الخدمة الذي تمنحه Render. اختبر `/health`، ثم سجل الدخول.
6. احتفظ بنسخة احتياطية دورية من قاعدة البيانات وراقب سجلات الخدمة والتنبيهات.

## تشغيل محلي للاختبار
- تحتاج Node.js 20+ وPostgreSQL.
- انسخ `.env.example` إلى `.env` واضبط بيانات PostgreSQL، و`JWT_SECRET`، و`ADMIN_EMAIL`، و`ADMIN_PASSWORD`.
- نفّذ `npm install` ثم `npm start` وافتح `http://localhost:3000`.

## ملاحظة أمنية
المشروع الأصلي احتوى كلمة مرور افتراضية وسر JWT ثابتًا؛ تم حذف اعتماد الإدارة الافتراضي الثابت من هذه الحزمة. اضبط أسرار الإنتاج من إعدادات الاستضافة، ولا ترفع ملف `.env` إلى GitHub.
